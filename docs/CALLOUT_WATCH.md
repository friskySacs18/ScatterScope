# Callout watch status — 2026-09-24

The homepage checks `/api/callouts/recent` every eight seconds while the tab is visible and at least one caller is saved. It matches Pump wallet IDs against the browser's saved watchlist, deduplicates call IDs, and displays observations without placing orders. The first successful poll is a baseline, so existing calls are not mislabeled as new.

The Worker requests Pump's per-caller `callout/list/{wallet}?limit=20` endpoint, checks that the response caller matches the requested wallet, and fails the whole check when one caller fails. Feed coverage and publication-to-observation latency have not been proven. The 8-second interval is a check cadence, not a measured detection latency. This browser watcher also stops when the page is closed or hidden.

## Background monitor prepared

`POST /api/automation/monitor-tick` reads authenticated account drafts, checks up to 50 distinct caller wallets on Pump, and stores unique, fresh Callout observations with timestamps in D1. It rejects missing, stale or invalid HMAC requests; a saturated/incomplete provider check records no observations. It never places an order. `scripts/pump-monitor.mjs` drives the endpoint every eight seconds on a supervised Node host. Configure a fresh 32+ character `SCOPE_MONITOR_SECRET` in both environments and set `SCOPE_MONITOR_URL` to the site's HTTPS `/api/automation/monitor-tick` route. A private Site additionally requires `SCOPE_SITE_ACCESS_TOKEN`. No always-on host or long-lived access credential has been set up, so this monitor is **not running continuously**. A dynamic Site token is not suitable as a permanent service credential.

The authenticated drafts endpoint requires `PRIVY_ACCESS_TOKEN_VERIFICATION_KEY` (the public key for app-issued login tokens). It remains unavailable until that key is configured. A saved draft does not prove ownership of the supplied Solana wallet and cannot grant signing permission. Before execution, independently bind the Privy user, their embedded wallet ID, and the signer consent.

`POST /api/automation/inspect-buy` structurally checks a version-zero, single-signer, SOL-paired Pump buy transaction. It requires a matching wallet and mint, exactly one Pump `buy`, and a `max_sol_cost` no greater than the selected spend, while rejecting extra programs, address lookup tables and oversized priority fees. It is read-only and cannot sign or submit. The cap on the Pump buy instruction does not include every fee or new account rent; a separate all-in funding reserve and spend ledger are still needed. Program changes and v2 Pump instructions fail closed until explicitly supported and tested.

Users choose their own three USD market-cap ranges and a SOL amount for each. There are no prefilled range or trade-size values. A fixed platform maximum is not applied to copy-trade rules; the selected range's SOL amount is the per-order maximum checked against the Pump buy instruction. Sizing requires a fresh, authenticated USD market-cap quote for the exact mint. The quote source and freshness guarantee have not been integrated into execution, so missing or stale quotes fail closed.

`caller_mint_history` stores the earliest **observed** call for each caller and coin, with `history_complete=0` until a complete historical archive has been verified. The eligibility check blocks repeats and unknown history; a short recent feed cannot establish a caller's first-ever call. `account_mint_locks` has a unique account/coin constraint intended to prevent additional buys even if different watched callers post the same coin. No live order service currently acquires these locks or marks purchases, and the execution switch is still off.

## Provider bridge prepared

An alternative read-only intake now accepts authenticated Callout observations from a long-running TweetStream WebSocket consumer. The consumer is `scripts/callout-stream.mjs`. Scope persists unique event IDs and publication/observation timestamps in D1, requires a fresh heartbeat every 30 seconds, and returns 503 when the source stops. Stale and malformed events are rejected. It never signs or broadcasts a transaction.

To operate it, configure `CALLOUT_INGEST_SECRET` as a 32+ character secret in the Site runtime. On an always-on Node 24 host configure `TWEETSTREAM_API_KEY`, `SCOPE_INGEST_URL` (the Site's HTTPS `/api/callouts/ingest` URL), `SCOPE_INGEST_SECRET` (the same value), `SCOPE_SITE_ACCESS_TOKEN` (a valid Site owner-only access credential), and `SCOPE_CALLER_MAP` (path to a JSON object of provider usernames mapped to verified Pump wallet addresses). Select those same accounts in the provider dashboard. Run `node scripts/callout-stream.mjs` under a supervised service. A provider subscription, Site access credential and always-on host are not currently configured. The browser's local watchlist is not yet synchronized to this provider map. Feed coverage and latency remain unmeasured. Do not route this intake to a signer until identity matching and actual signal coverage pass a prospective test.

The owner-only Site cannot be reached by an external background process without a Site access credential. Keep both credentials outside Git and rotate if exposed. `node scripts/test-callout-ingest.mjs` verifies signature rejection, deduplication, stale source shutdown and the zero-spend interlock against a mock D1 binding.

Before a live order route can be enabled: establish a permitted, reliable, timestamped Callout source; measure publication-to-observation latency and missing-call rate over actual caller samples; persist subscriptions and dedup state on an always-on process; validate caller identity and mint; implement an unattended signer with per-user caps, funding and withdrawal isolation, kill switch, quotes, slippage, transaction confirmation, reconciliation, and rollback. Phantom manual signing alone cannot execute unattended orders. Current execution controls remain locked with a zero SOL spending cap.
